# Zenith - Plano de Fechamento

Documento de requisitos vivo para terminar o Zenith. A ordem abaixo prioriza:

1. Correcoes que impedem uso confiavel do app.
2. Integridade de dados e regras de negocio.
3. Fluxos centrais de usuario.
4. Estetica, animacoes e acabamento.
5. Performance e limpeza tecnica.

## Fase 0 - Bloqueadores e Integridade

### Datas, horarios e duracoes

- [x] Validar inputs sem bloquear o dialog com comportamentos estranhos; quando invalido, manter o usuario na interface e exibir erro claro no proprio campo/tela.
- [x] Em desafio, impedir data de inicio ou conclusao no passado.
- [x] Em desafio, impedir data de inicio posterior a data de conclusao.
- [x] Em desafio, impedir data de conclusao anterior a data de inicio.
- [x] Em registro de atividade, impedir data de realizacao no futuro.
- [x] Em registro de atividade, impedir horario futuro quando a atividade for no dia atual.
- [x] Em registro de atividade, impedir duracao cujo horario final calculado seja maior que o horario atual.
- [x] Usar horario confiavel obtido pela internet/backend, nao o relogio local do dispositivo, para validacoes sensiveis.
- [x] Padronizar todos os seletores de data e horario com dialogs alinhados ao tema Zenith.
- [x] Usar wheel para duracao em todas as telas que exigem duracao.
- [x] Recriar `ZenithDateField`, `ZenithTimeField` e `ZenithDurationField` sem DatePicker/Dialog/Button/Surface do Material, usando superficie branca e bordas verdes do Zenith.
- [x] Corrigir a wheel Zenith para selecionar o valor centralizado, nao o item no topo da lista.

### Banco, RLS e publicacao

- [x] Corrigir `Infinite recursion detected in policy for relation "feed_entries"`.
- [x] Confirmar que `activity_mentions` nao apresenta mais recursao infinita em RLS.
- [x] Corrigir erro ao publicar: `Could not find the column "desafio_id" of posts in the schema cache`.
- [x] Revisar schema/cache do Supabase depois das migrations relacionadas a posts, desafios, atividades, mencoes e feed.

### Navegacao critica

- [x] Corrigir fluxo em que, apos finalizar uma atividade monitorada a partir da lista de desafios, nao e possivel voltar.
- [x] Ao tentar sair da revisao de atividade monitorada com alteracoes pendentes, avisar que as mudancas serao perdidas.
- [x] Adicionar paddings restantes de bottom navigation em listas/telas que ainda cortam conteudo, incluindo tela de titulo e historicos longos.

## Fase 7 - Acabamento e Qualidade

### Animacoes

- [ ] Adicionar animacoes nas telas acessadas pelo botao "Novo" na home: desafios, registrar e iniciar.
- [ ] Adicionar transicoes leves em tabs e seletores onde fizer sentido.

### Formatacao de unidades

- [x] Trocar exibicao em minutos crus por horas/minutos:
  - `600.0 min` deve virar `10h`.
  - `630 min` deve virar `10h30m`.
- [x] Em kilometros, remover decimal quando for zero.
- [x] Em kilometros, manter uma casa quando necessario, por exemplo `25,2km`.
- [x] Em passos, remover decimais sempre.

### Logs e warnings

- [ ] Remover ou silenciar corretamente o warning `Job was cancelled`, sem esconder erros reais.

## Criterios de Aceite Final

- [ ] `./gradlew --stop` executado antes da instalacao final.
- [ ] `./gradlew installRelease` executado no final de cada ciclo de implementacao relevante.
- [ ] App instala em device/emulador conectado ou falha apenas por ausencia de dispositivo.
- [ ] Fluxos principais testados manualmente:
  - registrar atividade;
  - iniciar/finalizar atividade monitorada;
  - criar desafio;
  - entrar em desafio ativo/finalizado;
  - abrir perfil proprio;
  - abrir perfil alheio;
  - abrir conquistas;
  - abrir feed e detalhe de atividade;
  - criar/acompanhar meta;
  - notificacoes e mencoes.
- [ ] Supabase advisors revisados apos migrations relevantes.
- [ ] Nenhum erro conhecido de RLS recursiva em telas usadas pelo app.
